# Changelog Research — Claude Code 릴리스 조사·검증

Claude Code의 신규 릴리스 정보를 정확하게 수집하고, 2개 이상의 출처로 교차검증하는 방법.

## 핵심 원칙

- **최신성 표방 = 정확성이 생명.** 이 책은 "최신 Claude Code 기준"을 표방하므로, 틀린 정보 1건이 책 전체 신뢰를 무너뜨린다. 조사보다 검증에 더 무게를 둔다.
- **차이(delta)만.** 이미 반영된 버전은 건너뛴다. `CHANGELOG.md` 최상단의 `> Claude Code X ~ Y 반영`이 기준선이다.
- **추측 금지.** 원문에서 확인되지 않은 기능·플래그·설정 키는 존재하지 않는 것으로 간주한다.

## 권위 있는 출처 (우선순위)

| 순위 | 출처 | 용도 |
|------|------|------|
| 1차 | 공식 CHANGELOG 원문(raw) | 버전별 변경의 1차 근거. 버전 번호·항목 원문 확인 |
| 1차 | 공식 문서 (code.claude.com/docs, docs.claude.com) | 기능 동작·용법·설정 키·플래그 확인 |
| 보조 | 릴리스 블로그·공지 | 모델 릴리스 등 맥락 보강 (단독 근거로는 부족) |

> 도구: `WebFetch`로 원문을 가져오고, `WebSearch`로 최신 릴리스 존재 여부를 확인한다. 접근 실패 시 재시도하지 말고 접근 가능한 출처로 진행하되 누락을 명시한다.

## 조사 절차 (release-tracker)

1. **기준선 확인**: `VERSION`, `CHANGELOG.md` 최상단에서 책이 커버하는 CLI 버전 범위를 읽는다
2. **신규 버전 수집**: 기준선 이후 출시된 CLI 버전의 CHANGELOG를 가져온다
3. **카테고리별 훑기**: 아래 축을 각각 확인한다 (한 곳에 뭉쳐 있지 않다)
   - 모델 릴리스 (새 Opus/Sonnet/Haiku, 기본 모델 변경, 노력 수준)
   - 슬래시 커맨드 (신규·변경·폐지)
   - 훅 이벤트 (신규 이벤트, 출력 필드)
   - 설정 키 (settings.json, 관리형 설정)
   - 환경 변수
   - CLI 플래그·서브커맨드
   - 스킬·플러그인·MCP 관련
4. **버전 귀속**: 각 항목을 "2.1.x에서 추가"처럼 버전에 붙인다
5. 불확실 항목은 `[확인 필요]`로 표시한다

## 교차검증 절차 (fact-verifier)

각 항목마다 다음을 수행한다:

1. **1차 출처 대조**: 공식 CHANGELOG 원문에서 해당 항목·버전을 찾는다
2. **2차 출처 대조**: 공식 문서에서 동작·용법을 확인한다
3. **책 내 중복 확인**: `grep -rn "키워드" docs/`로 이미 반영됐는지 확인한다
4. **정확 문자열 검증**: 플래그·설정 키·훅 이벤트·모델 ID의 철자·대소문자를 원문과 대조한다
5. **판정**: ✅확정(2-소스 일치) / ✏️수정(부정확) / ❌기각(환각·미확인) / ♻️이미반영 / 단일출처

### 반증 우선 사고
항목을 "맞다"고 확인하려 하지 말고, "틀렸다"고 가정하고 반증을 찾는다. 반증에 실패해야 확정한다. 특히 다음은 틀리기 쉬우니 주의:
- **기본값 반전** (예: 어떤 키의 기본 동작이 특정 버전에서 뒤집힘)
- **기능 재분리·이름 변경** (예: 폐지된 줄 알았던 커맨드가 다른 역할로 재도입)
- **버전 귀속 오류** (기능은 실재하나 도입 버전이 틀림)

## 환각 차단 체크리스트

- [ ] 플래그/설정 키/훅 이벤트/모델 ID가 원문에 **문자 그대로** 존재하는가
- [ ] 도입 버전이 원문과 일치하는가
- [ ] "그럴듯한데 원문에 없는" 기능은 아닌가 → 없으면 ❌기각
- [ ] 단일 출처에만 있으면 `단일출처`로 표시했는가
